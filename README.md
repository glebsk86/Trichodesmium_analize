# Trichodesmium: измерения по фотографиям

**Версия 0.7.0 — экспериментальный прототип для проверки человеком.**
Обрабатывает директорию снимков на macOS/Linux, ищет шкалы и вытянутые
объекты, измеряет видимые фрагменты и сохраняет CSV/XLSX, маски и вырезки.
Все найденные объекты — кандидаты. Определение вида пока не реализовано;
цветовое расширение настроено на девяти уникальных присланных фотографиях;
модель деревьев по-прежнему обучена только на первых шести. Независимой проверки нет. Не используйте выходные
данные для итоговой биомассы без визуальной проверки измерений.

Требования зафиксированы в [SPEC.md](SPEC.md), проверки — в [VALIDATION.md](VALIDATION.md).
Это локальный Git-репозиторий;
папка `.git` входит в архив. Подключённого GitHub-репозитория нет.

## Установка

Нужен Python 3.10 или новее. Откройте терминал в распакованной папке:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e '.[dev]'
trichodesmium --help
```

В **fish** (в том числе CachyOS) используйте `source .venv/bin/activate.fish`
вместо строки активации выше. Можно вообще не активировать окружение:
`.venv/bin/python -m pip install -e '.[dev]'` и затем
`.venv/bin/python -m trichodesmium ./photos -o ./results/run-001`.

Одни и те же команды предназначены для macOS и Linux. Проверено в Linux
на Python 3.12; запуск в macOS ещё не проверялся. GPU не нужен.
Первичная установка требует интернета для загрузки зависимостей;
обработка происходит локально.

## Готовый запуск Linux 0.7

Для CachyOS/Arch x86_64 подготовлен переносимый onedir-пакет с Python,
зависимостями, моделями и русским шрифтом. Нужна glibc ≥2.39. Его бинарная
проверка выполнена на Linux x86_64; на конкретном CachyOS пока не запускался.
Гайд: [packaging/GUIDE.html](packaging/GUIDE.html), текстовая версия —
[packaging/GUIDE.md](packaging/GUIDE.md). Весь `_internal` нужно оставить
рядом с исполняемым файлом. Интернет и установка Python при запуске не нужны.

Единый запуск из папки готовой сборки:

```bash
./trichodesmium ./photos -o ./results/local-001
```

Из исходников та же цепочка доступна через `trichodesmium-local` или
`python -m trichodesmium.local_app`. По умолчанию выполняются цветовой
детектор и B-уточнение. Основной результат — `index.html`, последовательные
PNG в `report/png-report`, `B-measurements.xlsx` и `B-measurements.csv`.
Таблицы первого этапа остаются отдельно в `seed-report`.

B-таблица содержит кандидатные оси, длину поддержанных участков и ширину
маски в рабочих px/мкм, масштаб и статус узлов. Вид, полная скрытая длина и
число клеток остаются неизвестными. Ошибки файлов сохраняются отдельно;
неопределённый масштаб не мешает пиксельному отчёту. Папки не перезаписываются.

Сборка воспроизводится из изолированного окружения разработки с
`pyinstaller>=6.10,<7`: `python packaging/build_linux.py`. Архитектура
и версия glibc, зависимости, коммит и состояние кода сохраняются в
метаданных сборки и манифесте каждого результата. Шрифт поставляется
с лицензией в `src/trichodesmium/assets/FONT-LICENSE.txt`.

## HEIC/HEIF с iPhone — 0.6.1

Можно помещать исходные `.HEIC`, `.heic` и `.heif` прямо в папку фото.
Регистр расширения не важен; команды обработки остаются теми же.
Декодер `pillow-heif` устанавливается автоматически вместе с проектом.
После замены прежней версии обновите зависимости из распакованного корня:

```bash
python -m pip install -e '.[dev]'
```

В fish без активации: `.venv/bin/python -m pip install -e '.[dev]'`.

Читается главное полноразмерное изображение HEIF, без промежуточного JPEG
и выбора миниатюры, глубины или вспомогательной HDR-карты. Вращение/отражение
контейнера обрабатывает декодер; EXIF не применяется к нему второй раз.
Если в контейнере несколько самостоятельных изображений, обрабатывается
только главное; выбранный индекс, число кадров и предупреждение сохраняются
в JSON. Многостраничный TIFF по-прежнему требует отдельных фотографий.

Исходный HEIC/HEIF сохраняется без изменения байтов в отчёте. Для браузера
создаётся полноразмерный `original-preview.png`, поэтому HEIC не требуется
отображать напрямую. Декодер, его версия, исходная разрядность и преобразование
цвета записываются в манифест. Встроенный ICC-профиль преобразуется в sRGB.
Если задан нестандартный NCLX без ICC, сохраняется предупреждение о необходимости
проверки цвета. Анализ остаётся **RGB8**: 10/12-битные данные приводятся к 8 битам,
вспомогательная HDR-карта не применяется. Это не обработка RAW/полного HDR.

Отправляйте фото как **оригинальные файлы**, сохраняя разрешение. Повышенное
разрешение само по себе не подтверждает точность разметки; калибровка по шкале
всё равно выполняется отдельно для каждого кадра. Основной B-сравниватель
сохраняет свою явную нормировку рабочей ширины, по умолчанию 960 px.

Поддержка проверена на настоящих синтетически закодированных HEVC-контейнерах
с разными ориентациями, 10-битным изображением и несколькими кадрами. Исходный
HEIC именно с телефона пользователя ещё не предоставлен для проверки.

## Концы, мкм и последовательный PNG-отчёт 0.6

Готовый результат: `results/tube-v0.6.0/index.html`. Для каждой фотографии
по числовому порядку: исходник, затем для каждого прошедшего фильтр B
кандидата **разметка** и **отдельное изображение измерений**. Полная
последовательность есть и в `png-report/*.png`, по одному PNG на фото.
Отклонённые гипотезы и сравнение A/B вынесены в `comparison.html`.
При отсутствии прошедших фильтр объектов написано «Ничего не найдено»;
ошибка чтения отдельно отмечается как ошибка, а не отсутствие объектов.
PNG объектов: `annotation.png` и `measurement.png` в папке выбранной оси.

Внешние колпачки ограничены исходной маской с допуском 1 px. Они сохраняют
видимый округлый конец, но не добавляют полукруг за плоским/неподдержанным
концом. Это исправляет дорисовку колпачков; исходная маска сама может
содержать ошибку и по-прежнему требует проверки.

Подписи содержат **мкм и рабочие px**. Пересчёт использует собственную
калибровку каждого исходника и его преобразование в рабочий растр. Даже
если размеры по X/Y различаются, длина каждого нарисованного вектора
пересчитывается по обеим координатам. Полная скрытая длина не выдаётся.
W остаётся шириной подобранной маски, а не проверенной шириной клеток.

Автоматический масштаб исходного отчёта используется только при наличии
поддержки отдельных мелких рисок. Если она отсутствует, мелкие риски
проверяются в окнах 240 px с шагом 120 px и сдвигом поперёк оси ±2 px.
Нужны согласованные периоды на **двух непараллельных осях**; крупные
риски не делятся автоматически на 10. Перекрывающиеся окна не являются
независимыми измерениями. Обе физические границы всей шкалы 600 мкм
не проверены. Дополнительно найденные шкалы исключаются из измерительных
участков. При неудаче мкм остаются пустыми, доступны px.

Проверка масштаба сравнивает только фото с **одинаковым исходным
разрешением**, порог предупреждения — 10% от медианы группы
(`--scale-tolerance 0.10`). Снимки разных разрешений не смешиваются.
Предупреждение не подгоняет масштаб и не отменяет собственную калибровку:
даже при одинаковых размерах файла цифровая обрезка может быть иной.
Общую ошибку масштаба всех кадров такая проверка не обнаружит.

Для воспроизведения используйте команду сравнения ниже с выходом
`-o results/my-v06-run`. Архив содержит полный новый отчёт, фотографии,
минимально необходимые исходные маски/манифесты 0.3 и историю Git.

## Плавные границы и линии измерений 0.5

У B добавлен мягкий бонус за прямые боковые линии и плавные изгибы с
большим радиусом относительно ширины. Оцениваются оба боковых края:
квадрат кривизны и частые изменения её направления. Круглые концы
ленты не штрафуются. Для всех семи гипотез используется одна исходная
ширина нормирования: сужение маски само по себе не даёт бонуса.
Вес по умолчанию 3; `--smoothness-weight 0` воспроизводит ранжирование
0.4. Плавность изменяет выбор/веса вариантов, а не делает все нити прямыми.
Окрашенная прямая стенка камеры может получить хороший балл формы;
отдельный фильтр помех и проверка принадлежности по-прежнему необходимы.

В `results/tube-v0.5.0/index.html` появились отдельные изображения
с линиями и подписями над каждым объектом:

- Голубые отрезки — ось поддержанных участков. **L участка** — сумма
  именно этих отрезков; через пробел, шкалу и неоднозначный узел не проходит
  подсчёт длины. Это не восстановленная полная длина всей цепи.
- Жёлтые поперечники — до 12 сечений, перпендикулярных оси. **W маски** —
  среднее длин этих же нарисованных линий. Это ширина подобранного контура,
  не независимая проверка внешней оболочки клетки. Исключены концы,
  неподдержанные участки, шкала и общие пиксели узла.
- Серая штриховая ось — геометрическая гипотеза, не участвующая в L.
  Отклонённые гипотезы не получают значений измерения.

Подписи и координаты используют **рабочие пиксели**, ширина рабочего
кадра 960 px. Преобразование из оригинала сохранено в отчёте; на
IMG_6805 рабочий пиксель отличается от исходного. Переход в мкм требует
проверенной шкалы: в предыдущем прогоне IMG_6809 был ошибочный крупный
период шкалы, а IMG_6808 не калиброван. Новая команда не подставляет эти
масштабы в подписи автоматически.

JSON `measurement_guides` хранит каждую линию/отрезок и её величину,
единицы, смысл и отсутствие физической калибровки. `measurement_overlay.jpg`
рядом с каждой осью показывает её линии; `ensemble-measurements.jpg`
показывает все оси B кадра. Отдельно записаны балл плавности, бонус,
цветовая часть оценки и веса всех гипотез.

## Сравнение изогнутых лент 0.4

Добавлена отдельная экспериментальная команда. Она получает **одинаковые
сохранённые кандидаты и оси** для двух моделей; обычная обработка фотографий
по-прежнему использует цветовой профиль 0.3.

- **A:** плавная центральная линия, мягкое ограничение ширины, уточнение
  двух краёв по точечной разнице окраски внутри и снаружи.
- **B:** семь вариантов ширины/положения на той же оси. С обеих сторон
  каждого края усредняется Lab в квадрате, затем считается разность,
  делённая на расстояние между центрами квадратов. Оценка объединяет
  модуль градиента и направленную разницу жёлто-оливковой окраски.
  Две границы должны иметь поддержку; веса — относительные оценки
  подгонки, не вероятность принадлежности к виду.

```bash
python -m trichodesmium.tube_compare \
  --seed-report results/colour-v0.3.0 \
  --seed-report results/extra-five-v0.3.0 \
  --source-dir data/user-nine \
  --source-dir data/extra-five-2026-10-05 \
  -o results/my-tube-comparison
```

В архиве готовый результат находится в `results/tube-v0.4.0/index.html`.
Можно указать один отчёт и одну папку фото. Для новых снимков сначала
создайте обычный отчёт `trichodesmium ./photos -o ./results/new-seeds`,
затем передайте его через `--seed-report`.

Рабочая ширина кадра — 960 px, пропорции сохраняются. Пробная минимальная
ширина ленты — 4 **рабочих пикселя**, квадрат — 2×2 px, меньше этого
минимума; это параметры эксперимента, а не установленная биологическая
ширина. Их меняют `--working-width`, `--min-width`, `--max-width`,
`--patch-side`. Разрешение и преобразование координат записываются явно.
Начиная с 0.6 сравнительный режим также пересчитывает доступные размеры в мкм.

Каждая ось отклоняется при слабой двусторонней границе, нестабильной
ширине, слишком малой длине относительно ширины или тесных изгибах.
Отклонённые гипотезы сохраняются серым контуром. Круглый мусор без
длинной оси отклоняется; длинный окрашенный мусор всё ещё может пройти.
Сложные сети без разрешимой оси остаются отдельным случаем для проверки.
Предположительные пересечения под углом от 25°, стыки концов и
перекрывающиеся маршруты по общей оси различаются; проверяются также
пары из разных исходных ID.
Узлы не получают единственного владельца: маски отдельных гипотез
хранятся раздельно, общие пиксели исключены из поддержанных участков.
Продолжение нити через сложный узел пока не установлено автоматически.

`template.png` — геометрическая гипотеза, допускающая мостики через
небольшие разрывы; `supported.png` — только участки с поддержкой обеих
границ, без шкалы и неоднозначных узлов. Эти маски не являются готовыми
измерениями. Все семь вариантов B и их веса сохранены рядом с выбранным.
Без оси исходного кандидата модели не найдут пропущенную нить. Сравнение
числа отбраковок и покрытия старой маски не доказывает точность.

## Цветовое выделение 0.3

По умолчанию используется `microscope-colour-20261005`. Он сравнивает
жёлто-оливковую окраску сердцевины с ближайшим фоном **по обеим сторонам**,
на 16 направлениях и трёх поперечных размерах. Уверенные предложения прежней
модели расширяются на слабые участки только при поддержке локального цвета
и более слабых голосов той же модели. Новые длинные цветные предложения
дополнительно требуют двух тёмных краёв. Модель не переобучалась.

Открытие маски, разрывавшее тонкие перемычки, для нового режима исключено.
Кривизна допускается: вытянутость проверяется по протяжённости скелета
относительно толщины; `--min-elongation` здесь задаёт нижнюю границу этого
отношения (не менее 6). В прежних режимах это по-прежнему отношение осей PCA.
Близкие фрагменты могут получить один ID при замыкании окрестностью 5 px,
но **добавленные замыканием пиксели не записываются в измерительную маску**.
При настоящем разрыве длина остаётся пустой. Принадлежность частей одному
трихому требует проверки; близкие разные нити могут ошибочно объединиться.
Изолированные пятна меньше 9 px удаляются; чрезмерное разрастание маленького
семени отклоняется. Число объектов не ограничивается заранее.

На последних шести фото новая разметка охватывает больше основной нити,
а на фото 12 находит ранее пропущенную цепь. Это не проверенные внешние
контуры: остаются разрывы, ответвления, пропуски коротких и бледных нитей.
В этом прогоне единые длины всех семи масок остаются пустыми. Цветовые пороги
и размеры относятся к этой серии 960×1280; другой свет или цифровой масштаб
потребуют новой проверки. Все параметры и предупреждения записываются в отчёт.

Для воспроизведения прежнего режима:

```bash
trichodesmium ./photos -o ./results/legacy-001 \
  --segmentation-profile microscope-20261002
```

Точный исходный код предыдущей версии сохранён в Git-теге `v0.2.0`.

## Автоматическая калибровка

```bash
trichodesmium ./photos --output ./results/run-001
```

По умолчанию расстояние между соседними рисками — **3 мкм**.
Размер пикселя вычисляется отдельно для каждой фотографии. Детектор ищет
длинную ось и повторяющиеся тёмные поперечные риски с обеих её сторон;
при двух найденных направлениях проверяет согласованность масштаба.
На повёрнутых шкалах работает без поворота исходного изображения.
Добавлен поиск слабых размытых делений с шагом около 3,8 пикселя: спектральный
период принимается только при поддержке расстояниями между отдельными рисками.
Односторонние риски, ещё более мелкие деления, цветная шкала или помехи могут
привести к отказу детектора. Совпадение с периодическим рисунком другого
объекта полностью исключить пока нельзя: проверяйте диагностику шкалы.

Полная линейка **600 мкм / 200 интервалов** хранится как справочная величина.
Программа пока не находит оба физических конца всей линейки автоматически.
Фрагмент шкалы не принимается за полные 600 мкм.

Если калибровка не удалась, подробный отчёт сохраняет размеры в пикселях,
а физические размеры остаются пустыми. Код завершения — 2. После проверки
можно перезапустить с ручным масштабом в новую директорию.

## Общий ручной масштаб

```bash
trichodesmium ./photos -o ./results/run-002 \
  --scale-mode manual --um-per-pixel 0.25
```

`0.25` — только пример, не готовый масштаб ваших снимков.
Применяется ко всем изображениям: разрешение и цифровое масштабирование
серии должны соответствовать заданному значению.

## Калибровка по референсу

По рискам на отдельном снимке:

```bash
trichodesmium ./photos -o ./results/run-003 \
  --scale-mode reference --reference ./calibration.jpg
```

По двум известным точкам на референсе:

```bash
trichodesmium ./photos -o ./results/run-004 \
  --scale-mode reference --reference ./calibration.jpg \
  --reference-points 100 200 500 200 --reference-distance-um 120
```

Здесь пример: от (100,200) до (500,200) — 120 мкм. Если вы отметили именно
два конца полной шкалы, укажите `--reference-distance-um 600`.
Координаты — пиксельные x,y после применения EXIF-ориентации, отсчёт от 0.
Используйте любой редактор, показывающий координаты курсора.
Автоматического окна для выбора точек в этой версии нет.

Перенос масштаба требует того же объектива, оптического тракта, зума и
цифровой обработки. Разные размеры фотографий в режиме референса вызывают
отказ от переноса. Одинаковый размер файла не доказывает одинакового зума.

## Исправленные маски

Откройте `results/run-001/index.html` в браузере. В галерее отдельно показаны
**исходный цветной фрагмент**, разметка и бинарная маска. Нажмите «Исправить
маску»: редактор работает без сервера и интернета, показывает весь снимок.
Выберите отдельный ID для каждой нити, настройте кисть в пикселях, уберите
ложные находки ластиком и дорисуйте видимые границы. Есть отмена штриха,
увеличение и восстановление исходных кандидатов. Нажмите «Скачать маску PNG»
для каждого фото и сложите файлы в `corrected_masks`.

```bash
trichodesmium ./photos -o ./results/reviewed-001 \
  --mask-dir ./corrected_masks --mask-format instances
```

Для `photos/IMG_6807.jpg` ожидается `corrected_masks/IMG_6807.png`.
С `--recursive` сохраняется относительный путь вложенных папок.
Все фотографии должны иметь соответствующую маску; отсутствие маски
отмечается ошибкой, без тихой подмены автоматическим выделением.

Маска должна содержать серые ID и совпадать по размеру с ориентированным
изображением: фон = 0, объекты = отдельные целочисленные ID (1,2,3,...).
Бинарные маски также допустимы, но соприкасающиеся нити в них станут одним
объектом. Маски можно подготовить вручную, в Fiji либо внешним сегментатором.
Редактор сохраняет PNG с одинаковыми RGB-каналами и непрозрачной альфой;
такие файлы также читаются как маски. **Сама маска с ID 1–3 выглядит почти
чёрной в обычном просмотрщике — это не фотография.** С `--mask-format instances`
разорванные части одного ID сохраняются вместе, и их единая длина остаётся
пустой. Без этого флага режим `auto` трактует маску с двумя значениями как
бинарную и разделяет связные области. Для внешних бинарных масок можно явно
задать `--mask-format binary`. В одной директории с масками избегайте двух
фотографий с одним именем и разными расширениями — обе будут искать один PNG.

| `images/<фото-ID>/overview.png` | Разметка всего кадра |

| `images/<фото-ID>/ruler_mask.png` | Предполагаемые шкалы/риски |

| `images/<фото-ID>/details.json` | Геометрия, профили шкалы/интенсивности, отдельные измерения |
| `images/<фото-ID>/widths.csv` | Отдельные значения ширины |
| `images/<фото-ID>/cell_intervals.csv` | Непроверенные интервалы между кандидатными перегородками |
| `images/<фото-ID>/obj_0001/` | Исходная вырезка, вырезка с пометками, бинарная маска |

Объекты обозначены красным контуром и ID; центральная линия — голубая;
поперечные измерения — зелёные; кандидатные перегородки — розовые;
предполагаемая шкала — полупрозрачная синяя область.
Убирайте вырезки параметром `--no-crops`, если они не нужны.

CSV используют UTF-8 с BOM и десятичную точку. При необходимости импортируйте
их через меню данных Excel с разделителем «запятая», либо откройте XLSX.

Ширина усредняется по поперечным измерениям вне концов и известных помех.
Длина — вдоль сглаженной центральной линии с продлением до границ маски.
Разветвлённые/замкнутые маски сохраняются, длина для них остаётся пустой.
Число клеток — **оценка** `округление(длина / средний интервал)`;
перегородки, найденные по текстуре, ещё не подтверждены как клеточные.
Скрытые фрагменты и целые цепи за пределами снимка не восстанавливаются.
При неудаче автоматического поиска шкалы её наложения также могут остаться
нераспознанными; проверяйте контуры даже при ручной калибровке.

Качество выдаётся категориями с причинами; это не вероятность правильности.
Виды всегда «не определён». Для обучения ML сначала исправьте маски и
идентификации, не используйте автоматически найденные объекты как готовую истину.

## Профиль выделения в 0.2

По умолчанию включён **`microscope-20261002`**: небольшой пиксельный классификатор
OpenCV на CPU, использующий цвет относительно ближайшего фона и текстуру.
Он настроен на всех шести снимках 960×1280, сделанных одним объективом.
Приблизительные штрихи по сердцевинам нитей заданы ассистентом; это **не
подтверждённые экспертом контуры**. Профиль и SHA-256 записываются в отчёт.
Чёрные края поля исключаются; фильтры площади, толщины и вытянутости убирают
мелкий мусор. Лимита «не больше трёх объектов» нет.

На шести снимках стало **1, 1, 2, 3, 3, 1 кандидатов** вместо **2, 8, 25, 27, 26, 22**
в присланном отчёте. Это сравнение числа строк, **не оценка точности**:
на фото 2 пропущена большая часть нисходящей нити, на фото 4 пропущены части
верхней нити, а на фото 5 три находки относятся к частям одной цепи.
Слабые участки, концы и прозрачные края часто не выделяются. Ширина маски
сердцевины может быть меньше настоящей ширины трихома. Исправляйте контуры
до использования физических размеров. Короткие ответвления скелета (не больше
локальной толщины и 12 пикселей) игнорируются с явным флагом; длинные ветви
и пересечения оставляют длину пустой. Другие размеры/окраска/разрешение
снимков могут потребовать нового профиля.

Общий детектор доступен отдельно:

```bash
trichodesmium ./photos -o ./results/generic-001 --segmentation-profile generic
```

В нём исправлены захват целого жёлтого фона и глобальная заливка дырок.
Параметры `--contrast` и `--saturation` относятся только к этому профилю.
Повторить обучение специального профиля можно через
`python tools/train_microscope_profile.py data/user-six ./new-profile.xml.gz`.
Для подключения новой модели требуется обновить её метаданные и контрольную
сумму; сами фотографии исключены из Git.
