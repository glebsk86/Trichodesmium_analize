# Trichodesmium 0.9.0

Промежуточный локальный прототип: фотографии → кандидаты B → HTML, PNG и CSV/XLSX.
Все определения и маски требуют визуальной проверки. Вид и число клеток не определяются.

## Основной запуск

Готовая Linux-сборка не требует установки Python. Распаковать всю папку,
сохранить `_internal` рядом с исполняемым файлом:

```bash
./trichodesmium "/путь/к/фото" -o "./results/run-001"
xdg-open "./results/run-001/index.html"
```

Из исходников (Python ≥3.10):

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e .
python -m trichodesmium "./photos" -o "./results/run-001"
```

Основные команды `trichodesmium`, `trichodesmium-local` и `python -m trichodesmium`
теперь запускают только B. A удалён из текущего кода, история сравнения сохранена
в ветке `compare-tubular-masks`. `trichodesmium-seeds` — отдельный диагностический
первичный детектор, не итоговая морфометрия.

## Изменения 0.9

- HEIC читается напрямую в RGB8 с ICC→sRGB и правильной ориентацией.
  Обработка семи оригиналов из IMG_70.zip использовалась при исправлении;
  это рабочая выборка, а не независимая оценка точности.
- B уточняет границы и измеряет на исходном разрешении. Первичный поиск
  остаётся ограниченным растром до 960 px для скорости; он ищет несколько
  ширин по двустороннему цвету и парным краям, без запрета старой моделью.
- Сглаживание, радиусы, соединение фрагментов и шаг проверки изгиба
  учитывают плотность пикселей. Масштаб не переносится между разными фото.
- При найденной шкале пробные радиусы задаются в мкм: по умолчанию 1.5–12.
  Это настраиваемые параметры поиска, а не нормативные размеры вида.
- Цветовые квадраты имеют сторону не менее 6 px. При калибровке сторона
  равна ceil(4.8 / мкм-на-пиксель), минимум 6. Без шкалы растёт с разрешением:
  960×1280 → 6×6; 3024×4032 → 19×19. Физические радиусы без шкалы не применяются.
- Если окно слишком велико для ширины нити, участок не признаётся
  поддержанной границей. Слишком тонкие нити могут требовать другого масштаба.

```bash
./trichodesmium "./photos" -o "./results/run-002" --min-radius-um 1.5 --max-radius-um 12 --patch-side-um 4.8
```

`--working-width 0` (по умолчанию) сохраняет исходное разрешение для B.
Можно явно задать уменьшенную ширину; пересчёт физических размеров сохранится.

## Результат

`index.html` → `report/index.html`: фото по порядку, исходник → разметка →
измерение каждого прошедшего фильтр кандидата. Пустые кадры и ошибки различаются.
`B-measurements.xlsx` / `.csv` содержат видимую и прослеженную длины, ширину маски,
калибровку и статус. CSV UTF-8 BOM, разделитель `;`.
`report/png-report` содержит сводные PNG. `report/diagnostics.html` содержит
диагностику только B. В `report/manifest.json` — параметры, исходники, геометрия,
соединения, декодирование и время каждого этапа.

Ширина маски не является независимо проверенной шириной клеток.
`L оси` не доказывает принадлежность всех участков одной биологической нити.
Общие маршруты нельзя автоматически суммировать для биомассы.
Короткие/слабые нити могут пропускаться; посторонние длинные объекты могут
попадать в кандидаты. Полнота выделения всей нити и ложные находки ещё требуют улучшения.

## Шкала и ввод

Поддержаны JPG/PNG/HEIC/HEIF/TIFF/BMP. Для подпапок — `--recursive`.
Сохранён исходный файл. HEIC: главный кадр, поворот/отражение, ICC→sRGB,
RGB8 без HDR-карты; PNG-предпросмотр. Пересохранение RGB в PNG само по себе
не меняет результат; отличия цвета/кадрирования/разрешения могут его менять.

Малое деление 3 мкм, вся шкала 600 мкм; видимая часть не считается всей шкалой.
Без уверенной калибровки остаются px. Ручной масштаб должен относиться к
исходному пикселю: `--scale-mode manual --um-per-pixel ЗНАЧЕНИЕ`.
Референс: `--scale-mode reference --reference ФАЙЛ --reference-points X1 Y1 X2 Y2
--reference-distance-um ДИСТАНЦИЯ`. Одинакового объектива недостаточно для
переноса масштаба между произвольно обрезанными фото.

Git-репозиторий локальный, `.git` включён в архив исходников. GitHub не подключён.

## Ветка Linux с параллельной обработкой

`linux-parallel` наследует исправления B из `main`. Только в этой ветке:
`--workers 0` (по умолчанию) выбирает до четырёх процессов по доступным CPU
и памяти, с резервом около 2 GiB на процесс для больших кадров; `--workers 1` — последовательный запуск; `--workers 2` / `4` — ручной.
Фото обрабатываются независимыми процессами через spawn, итоговый отчёт
упорядочен по именам. Внутренние потоки OpenCV/BLAS ограничены, чтобы не
создавать конкурирующие пулы. При ограниченной памяти авто выбирает меньше.

Это CPU-алгоритм; GPU не используется. Ветка macOS/Apple Silicon пока не
собрана: общие B-исправления в `main` работают последовательно. Параллельность
отдельной Linux-ветки не объявлена проверенной на Apple Silicon.

## Ограниченный вывод

Добавьте `--limited-output`: программа создаёт только `index.html`,
`B-measurements.csv` и `B-measurements.xlsx`. Картинки встроены в HTML;
отдельные PNG, маски, оригиналы, варианты и JSON не создаются. HTML можно
переносить одним файлом; ссылки на таблицы работают, если они рядом.
Алгоритм и численные определения длины/ширины остаются теми же.

```bash
./trichodesmium "./photos" -o "./results/summary-001" --limited-output --workers 2
```
