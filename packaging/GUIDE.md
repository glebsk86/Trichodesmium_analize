# Trichodesmium 0.8.0 — Linux x86_64 / CachyOS

Готовая переносимая сборка ветки linux-parallel. Python и зависимости внутри.
Нужна glibc ≥2.39. Распакуй всю папку: _internal должен остаться рядом.
Запуск из терминала, отчёт в браузере. Новая сборка не проходила повторный
полный прогон тестов и бинарную проверку по твоему указанию. На CachyOS
пользователя она пока не запускалась.

## Запуск

```bash
tar -xf trichodesmium-0.8.0-linux-x86_64.tar.gz
cd trichodesmium-0.8.0-linux-x86_64
./trichodesmium "/путь/к/папке/фото" -o "./results/run-001"
xdg-open "./results/run-001/index.html"
```

Замени путь в кавычках своим. Для подпапок добавь --recursive.
Если папка результата уже существует, выбери другое имя: файлы не перезаписываются.
Можно запустить без аргументов: программа спросит папку фото.

## Параллельность

```bash
./trichodesmium "./photos" -o "./results/run-002" --workers 2
```

Без --workers программа выбирает до 4 процессов по ядрам и доступной памяти.
--workers 1 — последовательно, --workers 0 — авто. Каждое фото обрабатывается
отдельным процессом; порядок итогового отчёта сохраняется. Для слабого ноутбука
начни с авто или 2. GPU не используется. Размер HEIC после декодирования
всё равно влияет на память, даже при нормализации анализа.

На семи предоставленных JPEG в среде разработки: последовательный запуск
54.97 с, четыре процесса 21.87 с, ускорение около 2.5×. Это не прогноз времени
твоего ноутбука и не сравнение с исходными HEIC. Повторные тесты пропущены.

## Ограниченные данные

```bash
./trichodesmium "./photos" -o "./results/summary-001" --limited-output --workers 2
xdg-open "./results/summary-001/index.html"
```

В папке только index.html, B-measurements.csv и B-measurements.xlsx.
Изображения встроены в HTML — файл можно переносить отдельно. Для ссылок
на таблицы держи CSV/XLSX рядом. Не создаются отдельные PNG, исходники, маски,
варианты и JSON. Алгоритм и определения измерений остаются теми же.

## Полный результат

index.html открывает report/index.html. Фото идут по именам: исходник,
затем разметка каждого кандидата и отдельное измерение. При отсутствии
прошедших фильтр объектов есть явное сообщение. Ошибки фото тоже показаны.
report/png-report — сводный PNG на кадр. report/diagnostics.html — диагностика B.
B-measurements.csv / .xlsx — таблицы. report/manifest.json — параметры,
версии, исходники, калибровка, линии, соединения фрагментов и время этапов.
run-info.json — общая сводка. Диагностический первичный A/B-отчёт не создаётся.

Основной алгоритм только B; A удалён из текущего кода и остался в истории Git.

## Как читать длину

L оси — вся прослеженная линия до концов маски. Промежутки через перекрытия
включены как оценка и показаны штрихом. Это не доказанная полная скрытая
длина биологической цепи. На пересечениях маршрут может быть неправильным.
L видимого — поддержанные участки; они показаны голубым. Их сумма меньше
L оси при перекрытиях. Невидимая часть оси указана в отдельной колонке.
W маски — средняя ширина по жёлтым сечениям; это не независимо проверенная
внешняя ширина клеток. Красный контур — гипотеза.

В XLSX сохранены прежние столбцы видимой длины; дальше добавлены «Длина
прослеженной оси» и «Невидимая часть оси». Для всей размеченной линии смотри
именно прослеженную ось. Виды и число клеток пока не определяются. Осей
может быть несколько для одной нити; нельзя автоматически суммировать
неоднозначные маршруты для биомассы.

## HEIC и масштаб

JPG, PNG, HEIC/HEIF, TIFF, BMP. Один главный кадр HEIC, поворот/отражение,
ICC→sRGB, RGB8; HDR-карта не используется. Оригинал сохраняется в полном режиме.
Любой формат после декодирования нормализуется до ширины 960 px перед
детектором, с сохранённым пересчётом координат и мкм. PNG из того же RGB
не улучшит алгоритм само по себе. Кадрирование, цвет и цифровой масштаб
могут менять результат. Реальные исходные HEIC новой серии не проверены:
приложенные IMG_7089–7099 — JPEG-копии.

Малый интервал шкалы 3 мкм, полная шкала 600 мкм. Видимый отрезок не считается
всеми 600 мкм. Калибровка отдельная для каждого снимка; согласованность
сравнивается только внутри одинакового исходного разрешения. Без найденного
масштаба остаются px. Не заполняй мкм догадкой.

Ручной масштаб должен быть измерен на исходном пикселе:

```bash
./trichodesmium "./photos" -o "./results/manual-001" --scale-mode manual --um-per-pixel 0.50
```

0.50 — пример команды, не универсальная калибровка. Для референса есть
--scale-mode reference, --reference, --reference-points X1 Y1 X2 Y2,
--reference-distance-um. Координаты после ориентации. Перенос разрешён при
одинаковом размере и цифровом/оптическом масштабе; один объектив недостаточен.

## Ограничения текущей версии

Алгоритм может пропускать короткие и слабые нити, объединять неверные
фрагменты и находить длинные помехи. Новая ассоциация соединяет только
близкие совместимые концы; при двух равноценных продолжениях узел остаётся
на проверку. На присланных семи JPEG найдено 9 кандидатных осей, а на
IMG_7098 и IMG_7099 пока нет прошедших фильтр находок. Автоматическая
калибровка получена только на двух кадрах. Это ещё не полная морфометрия.

## Если не запускается

Permission denied: chmod +x ./trichodesmium; при запрете запуска на диске
перенеси папку в домашний каталог. Не вынимай программу из _internal.
GLIBC_... not found: требуется glibc ≥2.39; понадобится совместимая пересборка.
Не запускай через sudo. Если параллельная обработка требует слишком много
памяти или сообщает ошибку процесса, попробуй --workers 1.

## Исходники и ветки

main: общий B, последовательный переносимый запуск и --limited-output.
linux-parallel: тот же B, плюс распределение фото по процессам на Linux.
compare-tubular-masks: историческое сравнение A/B.
.git входит в архив исходников. macOS/Apple Silicon ещё не собран и
параллельная Linux-ветка не объявлена проверенной на нём.
