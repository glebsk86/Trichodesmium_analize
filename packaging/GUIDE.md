# Trichodesmium 0.9.0 — Linux x86_64 / CachyOS

Python и зависимости включены. Требуется glibc ≥2.39, Linux x86_64.
Распакуй всю папку: _internal должен оставаться рядом с программой.

## Запуск

```bash
tar -xf trichodesmium-0.9.0-linux-x86_64.tar.gz
cd trichodesmium-0.9.0-linux-x86_64
./trichodesmium "/путь/к/фотографиям" -o "./results/run-001"
xdg-open "./results/run-001/index.html"
```

Для подпапок добавь --recursive. Папка результата должна быть новой.
Поддержаны HEIC/HEIF, JPG, PNG, TIFF и BMP. HEIC получает PNG-предпросмотр.
Исходник декодируется в полном разрешении, с поворотом и ICC→sRGB.

## Что изменено

B уточняет контур на исходном разрешении. Первичный цветовой поиск работает
на уменьшенном обзоре до 960 px, на нескольких ширинах, без обязательного
отбора старой моделью. Шаг сглаживания учитывает плотность пикселей.

Окна сравнения цвета минимум 6×6 px. Без шкалы: 960×1280 → 6×6,
3024×4032 → 19×19. При шкале: ceil(4.8 / мкм-на-пиксель), минимум 6.
При 0.25 мкм/px получается 20×20. Окна по обе стороны каждого бокового края;
если внутренняя область не помещается в нить, поддержка границы отклоняется.

Радиусы при калибровке по умолчанию 1.5–12 мкм. Это параметры поиска,
не норматив вида. Настройки:

```bash
./trichodesmium "./photos" -o "./results/custom-001" --min-radius-um 1.5 --max-radius-um 12 --patch-side-um 4.8
```

Без найденной шкалы физические радиусы не применяются: явно отмечается
пиксельный режим. Деление шкалы 3 мкм, вся шкала 600 мкм. Видимый участок
не растягивается до 600 мкм. Автоматическая шкала требует просмотра.
Ручные мкм/px относятся к исходному ориентированному снимку:

```bash
./trichodesmium "./photos" -o "./results/manual-001" --scale-mode manual --um-per-pixel 0.25
```

0.25 — только пример, не универсальная калибровка. Не переносить масштаб
между произвольно обрезанными кадрами только по одинаковому объективу.
--working-width 0 по умолчанию сохраняет исходник для B; можно явно уменьшить.

## Отчёт

Фото идут по порядку: исходник → разметка каждого кандидата → измерение.
При отсутствии прошедших фильтр объектов это написано явно. Ошибки отдельно.
report/png-report содержит сводные PNG. report/manifest.json содержит
параметры каждого фото, калибровку, декодирование, версии и причины отказов.
B-measurements.csv / .xlsx — таблицы. Вид и число клеток не определяются.

Красный контур — гипотеза. Голубая ось — измеренные видимые участки;
штрих — оценка в разрывах. L оси включает весь прослеженный путь, включая
помеченные оценки; L видимого — только поддержанные участки. W — ширина
маски. Невидимая длина и маршруты пересечений не считаются проверенными.
Ложные находки, пропуски и неполная разметка концов ещё возможны.

## Параллельность и краткий вывод

Авто выбирает число процессов по CPU и памяти, до четырёх, с резервом
около 2 GiB на процесс для больших исходников. --workers 2 задаёт два,
--workers 1 — последовательный запуск. GPU не используется.

```bash
./trichodesmium "./photos" -o "./results/summary-001" --workers 2 --limited-output
```

В ограниченном режиме только index.html со встроенными картинками,
B-measurements.csv и B-measurements.xlsx. Отдельные PNG/маски/JSON не создаются.

## Сборка и ограничения

Собрано в Linux x86_64 с glibc 2.39; на CachyOS пользователя не запускалось.
По твоему указанию повторный полный набор тестов и проверка бинарной
сборки пропущены. Оригиналы HEIC обработаны для настройки детектора и
создания приложенного отчёта. Это не независимая проверка точности.

Permission denied: chmod +x ./trichodesmium. GLIBC_... not found — нужна
совместимая версия glibc. При нехватке памяти используй --workers 1.
Не запускай через sudo. main — переносимый последовательный B;
linux-parallel — B плюс процессы Linux. Mac/Apple Silicon пока не собран.
A остался только в истории Git. Архив исходников включает Git-историю.
